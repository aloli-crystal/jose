Implémentation de JOSE (RFC 7515-7519) en Crystal pur : JSON Web
Signature (JWS), JSON Web Encryption (JWE), JSON Web Key (JWK).
Courbes elliptiques et RSA.

Version anglaise : link:README.adoc[README.adoc].

== Pourquoi

`jose` existe d'abord pour servir
https://github.com/aloli-crystal/crystal-clevis-geli[crystal-clevis-geli],
le client Tang pour les volumes GELI sous FreeBSD. Le périmètre
initial est volontairement minimal — uniquement ce dont le protocole
Tang a besoin :

* **JWK** : empreintes (RFC 7638), sérialisation, types de clés ECDH
  (P-256, P-384, P-521).
* **JWS** : ES256, ES384, ES512 (signature et vérification).
* **JWE** : accord de clés ECDH-ES, chiffrement de contenu A256GCM.

Depuis la v0.2, RSA est également pris en charge, pour une seconde
raison : OpenID Connect et WebAuthn signent tous deux en RS256 par
défaut. Une bibliothèque limitée aux courbes elliptiques ne peut donc
vérifier ni un jeton d'un fournisseur d'identité courant, ni une
assertion d'un authentificateur Windows Hello.

* **JWK** : `RSAKey` — génération, lecture et sérialisation JWK,
  empreintes, DER PKCS#1 / PKCS#8 / SubjectPublicKeyInfo.
* **JWS** : RS256, RS384, RS512 (signature et vérification).

Toujours hors périmètre (à ajouter plus tard si besoin) :

* RSA-OAEP et RSA-PSS (`PS256`, …).
* EdDSA (Ed25519).
* Validation JWT complète (`exp`, `nbf`, `aud`, …).
* Endpoints JWKS (découverte de clés via HTTP).

== Installation

Ajouter à votre `shard.yml` :

[source,yaml]
----
dependencies:
  jose:
    github: aloli-crystal/jose
    version: ~> 0.2
----

Puis `shards install`.

== Utilisation

[source,crystal]
----
require "jose"

# === JWK, courbe elliptique =========================================
key = Jose::JWK::ECKey.generate(Jose::JWK::Curve::P256)
key.thumbprint_base64url   # => "cn-I_WNMClehiVp51i_0VpOENW1upEerA8sEam5hn-s"
key.public_key.to_json     # => {"kty":"EC","crv":"P-256","x":"...","y":"..."}

# Parser un JWK (par exemple depuis un advertisement Tang).
peer = Jose::JWK::ECKey.from_json(jwk_string)

# === JWS, courbe elliptique =========================================
jws = Jose::JWS.sign("payload", Jose::JWS::Algorithm::ES256, key)
payload = Jose::JWS.verify(jws, key.public_key)

# === JWE ============================================================
jwe = Jose::JWE.encrypt("secret", peer.public_key)
plaintext = Jose::JWE.decrypt(jwe, peer)

# === RSA ============================================================
rsa = Jose::JWK::RSAKey.generate(2048)
rsa.modulus_bits           # => 2048
token = Jose::JWS.sign("payload", Jose::JWS::Algorithm::RS256, rsa)
payload = Jose::JWS.verify(token, rsa.public_key)

# Vérifier un jeton émis par un fournisseur d'identité : on prend le JWK
# qu'il publie et on contrôle le jeton avec.
idp_key = Jose::JWK::RSAKey.from_json(published_jwk)
claims = Jose::JWS.verify(id_token, idp_key)
----

L'algorithme et le type de clé doivent concorder : signer en `RS256`
avec une `ECKey`, ou en `ES256` avec une `RSAKey`, lève une erreur
plutôt que de produire un comportement surprenant. `Algorithm#family`
indique quel type de clé attend un algorithme donné.

NOTE: Une `RSAKey` privée a besoin de ses membres CRT (`p`, `q`, `dp`,
`dq`, `qi`) pour pouvoir signer. La RFC 7518 les rend facultatifs dans
un JWK, mais OpenSSL ne sait pas construire une clé à partir de `n`,
`e` et `d` seuls. `#crt_complete?` indique s'ils sont présents ; la
vérification avec une clé publique n'est pas concernée.
